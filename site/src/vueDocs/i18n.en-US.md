# Internationalization

The default language of `@hiltonkohler21/ant-design-vue` is English. To use another language, configure `ConfigProvider` and your date library locale as shown below.

## ConfigProvider

`@hiltonkohler21/ant-design-vue` provides [ConfigProvider](/components/config-provider) to configure component UI copy globally. Date formatting in time components is handled by the underlying date library (`dayjs` by default), so you should also import and activate the matching `dayjs` locale.

```vue
<template>
  <a-config-provider :locale="locale">
    <a-space direction="vertical">
      <a-radio-group v-model:value="lang" @change="onLocaleChange">
        <a-radio-button value="en">English</a-radio-button>
        <a-radio-button value="zh-cn">简体中文</a-radio-button>
      </a-radio-group>
      <a-date-picker />
      <a-pagination :total="50" show-size-changer />
    </a-space>
  </a-config-provider>
</template>

<script setup lang="ts">
import { computed, ref } from 'vue';
import enUS from '@hiltonkohler21/ant-design-vue/es/locale/en_US';
import zhCN from '@hiltonkohler21/ant-design-vue/es/locale/zh_CN';
import dayjs from 'dayjs';
import 'dayjs/locale/zh-cn';

const lang = ref<'en' | 'zh-cn'>('en');
dayjs.locale('en');

const locale = computed(() => (lang.value === 'zh-cn' ? zhCN : enUS));

const onLocaleChange = () => {
  dayjs.locale(lang.value);
};
</script>
```

> Note: `fr_FR` is the filename under `@hiltonkohler21/ant-design-vue/es/locale/`. If date localization does not take effect, ensure `dayjs.locale(...)` is called and verify with `npm ls dayjs` that duplicate versions of `dayjs` are not installed.
